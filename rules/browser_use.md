# Browser Use Policy

1. **Default tool & profiles**: Use the standalone `browser-use` MCP server (`src/server.js`, v4.6.0 / extension v0.6.0) for browser UI tasks: navigation, multi-tab workflows, Chrome tab group naming (`browser_name_session` / `browser.nameSession()`), form interaction, DOM/AX/content/console/network inspection, viewport emulation, uploads/downloads, and screenshots. Supports `--profile compact|standard|full` (`BROWSER_USE_TOOL_PROFILE`): `compact` registers 7 core tools (`browser_run`, `browser_batch`, `browser_get_state`, `browser_goto`, `browser_list_tabs`, `browser_screenshot`, `browser_end_turn`) reducing schema tokens by ~78% (~7.4K → ~1.5K tokens) for non-lazy CLI clients, while `full` (36 tools) remains default for lazy-loading clients. Prefer API/CLI/`curl` tools when browser UI interaction is unnecessary.
2. **1-shot scripting, batch & token-saving execution**:
   - Start with `ariaSnapshot({ mode })` (with child iframe trees) or diff-first `ax.write()` / `browser_get_state({ mode })` (`"full" | "compact" | "interactive"`, collapsing repetitive rows and pruning static boilerplate) before guessing CSS selectors. Use `browser_get_content` and `page.content.export()` / `.tables()` / `.links()` (`format: "markdown" | "tables" | "links" | "text"`) for structured extraction; `not_found` locator timeouts include closest-locator fallback hints.
   - Prefer `browser_run` (persistent context across calls, `reset_context: true` to clear, persistent in-page locator runtime cache `globalThis.__buRt` v1 at ~150-300 B/call, cached content script readiness, non-blocking virtual cursor via `BROWSER_USE_CURSOR_MODE=fast|smooth|off` with default `fast` = 0 ms, bound `browser.tabs.new()` handles, auto-claimed `target="_blank"` popups with `page.waitForEvent("popup")`, rich-text smart fill for CKEditor 4/5, TinyMCE, Quill, and `contenteditable`, `page.webmcp.listTools()`/`invokeTool()`, `page.assets.list()`, `evaluate(fn, arg)`, `setViewport()`/`resetViewport()`, `waitForEvent("filechooser"|"download")`, `tab.dev.logs()`/`network()`, and inline `markDeliverable()`/`markHandoff()`/`keep`).
   - Prefer `browser_batch` for known linear step sequences (including `get_state`, `get_content`, `read_tab`, `evaluate`, `set_viewport`/`reset_viewport`, optionally with `end_turn: true, keep: "deliverable"`) instead of sequential single-action round-trips.
   - `browser_goto` auto-creates a tab when none exists and returns `<ax_state>` directly.
   - Use diff-first `browser_get_state` (`screenshot: false` by default) and `ax.write()`, requesting screenshots (`screenshot: true` or `ax.write("screenshot")`, JPEG quality 75, `max_width` default 1280px) only when visual inspection is required.
3. **Read-only evaluate**: Use `browser_evaluate`, `browser_batch` `evaluate` steps, and `evaluate(fn, arg)` strictly for read-only page inspection (including read-only `classList`/`dataset`/`style` reads); perform mutations via action and locator tools.
4. **Session tabs & passive reading of existing user tabs**:
   - Use `browser_list_tabs` (or `browser.tabs.list()` / `browser.user.openTabs()` in `browser_run`) to find an already-open Chrome tab when the user asks to inspect or control an existing tab. For read-only inspection, prefer zero-debugger passive reading via `browser.tabs.read(id)` / `browser.user.getTabContext(id)` or passive `browser_get_content` (`chrome.scripting.executeScript` without attaching the Chrome debugger). Only claim/activate a tab with `browser_select_tab` (or `browser.tabs.get(tab_id)` / `browser.user.claimTab(tab)`) when interaction is needed; claimed user tabs are automatically released (never closed) when the turn ends.
   - Respect authentication, CAPTCHA, and site permission boundaries. When user sign-in or approval is needed, mark the tab `handoff` in `browser_end_turn` and ask the user directly.
5. **Turn cleanup**: End browser workflows with `browser_end_turn` (or inline `end_turn`/`keep` with `handoff` or `deliverable` when a tab must remain open).
